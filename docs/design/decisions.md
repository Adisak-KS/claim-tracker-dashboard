## 2026-09-12 · แยกรายงานตามธง AllowClaim

**ตัดสินใจ:** นับรายการที่ `AllowClaim = N` แยกจาก `Y`

**ทำไม:** สองอย่างนี้คนละความหมายทางธุรกิจสิ้นเชิง

ถ้าเอามารวมกันเป็น "ส่งไม่สำเร็จ" ก้อนเดียว ผู้บริหารจะไม่รู้ว่าเสียเงินไปเท่าไร

## 2026-09-12 · เก็บ vn/an ได้ แต่ hn ต้อง hash

**ตัดสินใจ:** เก็บ `vn`, `an` ตรง ๆ · `hn` เก็บเป็น hash เท่านั้น

**ทำไม:** vn กับ an เป็นเลขอ้างอิงภายในของโรงพยาบาล เปิดดูเฉย ๆ ไม่รู้ว่าใคร
แต่ hn เป็นเลขประจำตัวผู้ป่วยที่ผูกทุก visit ของคนเดียวกัน
เก็บ hn ดิบ = ระบบนี้กลายเป็นระบบข้อมูลส่วนบุคคลตาม PDPA
ซึ่งขัดกับข้อกำหนดของโปรเจกต์เอง

เก็บเป็น hash ยังตอบได้ว่า "คนไข้รายเดิมมีปัญหาซ้ำกี่ครั้ง" โดยไม่รู้ว่าเป็นใคร

**ยังไม่สรุป:** เจ้าของงานยังไม่ยืนยันข้อนี้ ต้องถามก่อนลงมือ Phase 2

**ทางเลือกที่ไม่เอา:** เก็บรหัสช่องเดียวแล้วแปลงเอา

## 2026-09-12 · ใช้ CSS อย่างเดียวทำ animation ไม่เพิ่มไลบรารี

**ตัดสินใจ:** ทำระบบ animation ด้วย CSS custom property กับ keyframes
ไม่ติดตั้ง Framer Motion หรือ GSAP

**เหตุผล:** จอนี้เป็นแดชบอร์ดข้อมูลหนัก ตารางเดียวมีได้ 100 แถว
ไลบรารี animation กิน bundle เพิ่มหลักร้อย KB แลกกับสิ่งที่ CSS ทำได้อยู่แล้ว
ท่าที่ใช้จริงมีแค่ 3 อย่าง (rise, pop, fade) ซึ่งไม่ต้องใช้ timeline หรือ spring

**โทเคนอยู่ที่ `globals.css` ห้ามใส่ตัวเลข duration ดิบในไฟล์ component**
ถ้าแต่ละจอตั้งเวลาเอง จอจะเคลื่อนไหวไม่พร้อมกันแล้วดูรก

| โทเคน | ใช้กับ |
|---|---|
| `--duration-micro` 140ms | hover ปุ่ม การ์ด |
| `--duration-state` 220ms | เปลี่ยนสถานะ เปิดปิด |
| `--duration-panel` 280ms | แผงขยาย |
| `--duration-enter` 420ms | เนื้อหาเข้าจอ |

**ไม่ใช้ easing แบบเด้ง (elastic/bounce)** เพราะเป็นระบบการเงิน
การเคลื่อนไหวที่เล่นเกินไปทำให้ดูไม่น่าเชื่อถือ

**ทุกท่าถูกปิดเมื่อผู้ใช้ตั้ง `prefers-reduced-motion`**
เหลือแค่ fade 1ms เพื่อให้เนื้อหายังแสดงครบ ไม่ใช่หายไปทั้งก้อน

## 2026-09-12 · ลงทะเบียน scheme ต้องทำในไฟล์ที่หน้าจอ import จริง

**ปัญหาที่เจอ:** `lib/schemes/index.ts` มีหน้าที่ลงทะเบียนประเภทการส่งเคลม
แต่ไม่มีไฟล์ไหน import มันเลย ทะเบียนจึงว่างจนกว่าจะมีใครเผลอ import
ไฟล์ที่ลากมันมาด้วย หน้าแรกรอดเพราะ generator ดึงไปโดยบังเอิญ
พอสร้างหน้าใหม่ที่ไม่ได้ผ่าน generator หน้าจอพังทันทีด้วย error
"ยังไม่ได้ลงทะเบียนประเภทการส่งเคลมใด ๆ"

**ตัดสินใจ:** ทุกไฟล์ที่เรียก `getScheme` `getDefaultScheme` `getIssueLabel`
ต้อง `import "@/lib/schemes"` ที่หัวไฟล์ของตัวเอง

**ทางเลือกที่ไม่เอา:** import แค่ใน root layout ที่เดียว
ลองแล้วไม่พอ เพราะ client component bundle แยกกันคนละก้อนกับ layout
พึ่งลำดับ import แบบนั้นคือกับดักที่ build ผ่านแต่พังตอนผู้ใช้กด

**หลุดซ้ำรอบสอง** หน้าแรกโชว์ `LOCAL_NO_INVOICE` `G30` เป็นรหัสดิบ
เพราะ `providers-need-help.tsx` เรียก `getIssueLabel` แต่ไม่ได้ import ทะเบียน
อาการคือ **ไม่มี error ให้เห็นเลย** แค่ได้รหัสดิบแทนชื่อไทย ซึ่งคนที่ไม่รู้จักรหัสจะดูไม่ออกว่าผิด
จึงใส่ `console.error` ตอน dev เมื่อทะเบียนว่าง ให้ดังตั้งแต่ตอนเขียนโค้ด

## 2026-09-12 · Export Excel ใช้ exceljs ทำฝั่งเบราว์เซอร์

**เลือก `exceljs` 4.4.0** (เช็คเมื่อ 12 ก.ย. 2569)

ไม่เลือก `xlsx` (SheetJS) เพราะบน npm ค้างที่ 0.18.5 มาตลอด
รุ่นใหม่ย้ายไปแจกบน CDN ของตัวเอง และตัวฟรีจัดรูปแบบเซลล์ไม่ได้เลย

## 2026-09-12 · หัวตาราง sticky ต้องทำครบ 3 อย่าง ขาดข้อเดียวก็พัง

**อาการ:** เลื่อนตารางแล้วตัวหนังสือของแถวข้อมูลวิ่งทะลุขึ้นมาซ้อนหัวตาราง
อ่านไม่ออกทั้งคู่ เหมือนมีตัวหนังสือซ้อนอยู่ด้านหลัง

**เดาผิดไป 1 รอบ** รอบแรกคิดว่าเป็นเพราะใส่ `bg` ไว้ที่ `<thead>`
ย้ายไป `<th>` แล้วยังพังเหมือนเดิม สาเหตุจริงคือข้อ 1 ข้างล่าง

ต้องทำครบทั้ง 3 ข้อ

1. 🔴 **ตารางต้องเป็น `border-separate` ไม่ใช่ `border-collapse`**
   นี่คือสาเหตุหลัก เมื่อ `border-collapse` เบราว์เซอร์จะไม่วาดพื้นหลัง
   ให้เซลล์ที่ sticky แถวข้อมูลจึงมองทะลุขึ้นมาเห็น
2. `sticky` กับพื้นหลังต้องอยู่ที่ `<th>` ไม่ใช่ `<thead>`
   เพราะเบราว์เซอร์ไม่ทำ sticky ให้ `<thead>` ตรง ๆ มันเกาะที่เซลล์แต่ละตัว
3. ต้องเว้น `top-14` ให้พ้น Topbar ไม่งั้นหัวตารางมุดหายไปข้างใต้

**ผลพลอยได้จาก `border-separate` ที่ต้องแก้ตาม**

- เส้นคั่นใต้หัวตารางใช้ `box-shadow` แทน `border`
- เส้นคั่นระหว่างแถวต้องวาดที่ `<td>` ไม่ใช่ `<tr>`
  เพราะ border ของ `<tr>` จะไม่ถูกวาดเมื่อ `border-separate`
  จึงมี `DataTableRow` คุมให้ ห้ามใช้ `<tr>` ดิบในตาราง
