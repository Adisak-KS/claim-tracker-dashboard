# ระบบการออกแบบ (Design System)

กติกาหน้าตาของระบบ ใช้ให้เหมือนกันทุกหน้า
ค่าจริงทั้งหมดอยู่ใน `frontend/src/app/globals.css`

## สี

สีหลักมาจากโลโก้ BMS จริง (หัวใจแดง เส้นโค้งน้ำเงิน)
ไม่ได้เลือกจากเทมเพลตสำเร็จรูป

### สีแบรนด์

| สี | ค่า | ใช้ตรงไหน |
|---|---|---|
| น้ำเงิน BMS | `#2B62B3` | สีหลัก เมนู ปุ่มหลัก ตัวเลขสำคัญ |
| แดง BMS | `#E8232A` | โลโก้เท่านั้น |

### สีสถานะ

| ความหมาย | token | ใช้ตอน |
|---|---|---|
| สำเร็จ | `success` | ส่งเคลมผ่าน โอนเงินเรียบร้อย |
| ผิดพลาด | `danger` | ส่งไม่สำเร็จ ระบบล่ม |
| เตือน | `warning` | อัตราสำเร็จต่ำ ใกล้ครบกำหนด |
| ทั่วไป | `info` | ข้อความบอกข้อมูลเฉย ๆ |

### 🔴 กฎเรื่องสีแดง

**แดงสงวนไว้ให้สถานะผิดพลาดเท่านั้น** ห้ามเอาไปตกแต่งหรือเน้นข้อความ

เหตุผล: แดงอยู่ในโลโก้ด้วย ถ้าใช้แดงพร่ำเพรื่อผู้ใช้จะเลิกสังเกตว่าแดงคือของเสีย
พอมี error จริงจะมองไม่เห็น

### กฎเรื่องการสื่อความด้วยสี

**สีอย่างเดียวไม่พอ** ทุกที่ที่ใช้สีบอกสถานะ ต้องมีไอคอนหรือข้อความกำกับด้วย
คนตาบอดสีมีประมาณ 8% ของผู้ชาย ถ้าใช้สีอย่างเดียวคนกลุ่มนี้อ่านไม่ออกเลย

## ฟอนต์

**IBM Plex Sans Thai** ทั้งระบบ

เหตุผลที่เลือกตัวนี้:
- มี glyph ไทยจริง (ไม่หลุดไป fallback)
- ตัวไทยกับตัวอังกฤษเป็นตระกูลเดียวกัน วางคู่กันแล้วดูเป็นฟอนต์เดียว
- วรรณยุกต์อยู่สูง เหมาะกับตารางที่บรรทัดชิด

### 🔴 ห้ามใช้

Inter, Geist, Space Grotesk, Roboto และฟอนต์ Latin ทั่วไป
**ไม่มี glyph ไทย** ภาษาไทยจะหลุดไปฟอนต์สำรองของเบราว์เซอร์
กลายเป็นหน้าจอสองบุคลิก และสระวรรณยุกต์ลอยเพี้ยน

ทดสอบด้วยข้อความไทยที่มีวรรณยุกต์ซ้อนจริง เช่น "กำลังตรวจสอบข้อมูลผู้ป่วย"
ไม่ใช่ทดสอบด้วย Lorem ipsum

## ตัวเลข

- ใช้ `font-variant-numeric: tabular-nums` ทั้งระบบ
  เลขจึงกว้างเท่ากันทุกตัว ตอน refresh ตัวเลขไม่ขยับซ้ายขวา
- เลขใหญ่ย่อให้อ่านไว: `11.59 ล้าน` ไม่ใช่ `11,586,657`
- เลขในตารางแสดงเต็ม เพราะต้องเอาไปกระทบยอด

## ไอคอน

**lucide-react เท่านั้น** ทั้งระบบ ชุดเดียว ความหนาเส้นเท่ากัน

### 🔴 ห้ามใช้ emoji เป็นไอคอน

เหตุผล:
- แต่ละเครื่องแสดงคนละแบบ (Windows กับ iPhone คนละหน้าตา)
- คุมสี ขนาด ความหนาไม่ได้
- เป็นสัญญาณอันดับหนึ่งที่คนดูออกว่า AI ทำ

## ระยะห่าง

ระบบนี้เป็น dashboard ข้อมูลแน่น ใช้ระยะห่างชิดกว่าเว็บทั่วไป

| ระดับ | ค่า | ใช้ตอน |
|---|---|---|
| ในการ์ด | 16px (`p-4`) | ระยะขอบในการ์ด |
| ระหว่างการ์ด | 12px (`gap-3`) | ช่องไฟระหว่างการ์ด |
| ขอบหน้า | 16px มือถือ / 24px จอใหญ่ | ขอบนอกสุด |

## Responsive

| ขนาดจอ | พฤติกรรม |
|---|---|
| < 640px (มือถือ) | การ์ด KPI เรียงลงมา 1 คอลัมน์ เมนูซ่อน |
| 640-1024px (แท็บเล็ต) | KPI 2 คอลัมน์ เมนูยังซ่อน |
| >= 1024px (โน้ตบุ๊ก) | เมนูแสดงถาวร ย่อเหลือไอคอนได้ |
| >= 1280px (จอใหญ่) | KPI 4 คอลัมน์ กราฟกับอันดับปัญหาอยู่แถวเดียวกัน |
| จอใหญ่มาก (ทีวี) | จำกัดความกว้างที่ 1920px ไม่ปล่อยเนื้อหากองกลางจอ |

**ตารางกว้างให้ scroll ในกล่องตัวเอง** ห้ามดันทั้งหน้า scroll แนวนอน

## สถานะการโหลด

ทุกจอที่ดึงข้อมูลต้องมี skeleton ไม่ใช่จอว่างหรือคำว่า Loading เปล่า ๆ

**skeleton ต้องมีจำนวนแถวและความสูงเท่าของจริง**
ไม่งั้นพอข้อมูลมาแล้วหน้าจะกระโดด ผู้ใช้กดผิดที่

## ปุ่ม

- ทุกปุ่มมีไอคอนคู่กับข้อความที่บอกว่าทำอะไร
- ปุ่มที่ทำงาน async ต้อง disable ระหว่างทำงาน และคืนสถานะใน `finally` เสมอ
  (`components/ui/button.tsx` ทำให้แล้วโดยอัตโนมัติ)
- ปุ่มอันตราย (ลบ ยกเลิก) แยกตำแหน่งจากปุ่มปกติ และต้องถามยืนยันก่อน

## ข้อความแจ้งเตือน

เขียนให้คนทั่วไปที่ไม่ใช่ dev เข้าใจ ต้องบอก 2 อย่างเสมอ

1. เกิดอะไรขึ้น
2. ต้องทำอะไรต่อ

```
ห้าม:  "เกิดข้อผิดพลาด"
ห้าม:  "Error 500: Internal Server Error"
ห้าม:  "Failed to fetch"
ใช้:   "ระบบขัดข้องชั่วคราว กรุณารอสักครู่แล้วกดลองใหม่อีกครั้ง"
```
