## ภาพรวม (`/`)

**ตอบคำถาม:** วันนี้ระบบโดยรวมโอเคไหม มีอะไรต้องรีบจัดการ

ผู้บริหารเปิดมาต้องรู้ภายใน 5 วินาที จึงเรียงจากกว้างไปแคบ

| ส่วน | แสดงอะไร |
|---|---|
| KPI 4 ใบ | ส่งไปกี่รายการ · สำเร็จกี่ % · ไม่สำเร็จกี่รายการ · รพ. ที่ติดปัญหากี่แห่ง |
| กราฟแนวโน้ม | เทียบสำเร็จกับไม่สำเร็จรายวัน เห็นว่าดีขึ้นหรือแย่ลง |
| อันดับปัญหา | 5 อันดับแรก พร้อมลูกศรบอกว่าพุ่งขึ้นหรือลดลง |
| รพ. ที่ต้องช่วยด่วน | เรียงตามจำนวนที่ส่งไม่สำเร็จมากสุด |

**ทำไมมีลูกศรแนวโน้ม:** ปัญหาที่มี 9,000 ครั้งแต่พุ่ง 31% สำคัญกว่า
ปัญหาที่มี 30,000 ครั้งแต่นิ่งมาตลอด เพราะตัวแรกคือของใหม่ที่กำลังพัง

---

## โรงพยาบาล (`/hospitals`)

**ตอบคำถาม:** โรงพยาบาลที่ผมดูแลเป็นยังไงบ้าง

- ค้นหาด้วยชื่อ รหัส หรือจังหวัด
- กรองตามเขตสุขภาพ ระบบต้นทาง สถานะ
- เรียงตามจำนวนที่ส่งไม่สำเร็จ อัตราสำเร็จ หรือชื่อ
- แบ่งหน้าฝั่งเซิร์ฟเวอร์ เพราะมี 5,000+ แห่ง

**สถานะพิเศษที่ต้องมี:** "เงียบผิดปกติ" คือ รพ. ที่เคยส่งแล้วจู่ ๆ หยุดส่ง
อันนี้อันตรายกว่าส่งไม่สำเร็จ เพราะไม่มี error ให้เห็นเลย

### โรงพยาบาลรายตัว (`/hospitals/[code]`)

- ประวัติการส่งย้อนหลัง
- กราฟอัตราสำเร็จของ รพ. นี้
- ปัญหาที่ รพ. นี้เจอบ่อยที่สุด พร้อมวิธีแก้

ทีมฝึกอบรมใช้หน้านี้เตรียมตัวก่อนไปสอน

---

## การส่งเคลม (`/submissions`)

**ตอบคำถาม:** รายการที่ยิงเข้ามามีอะไรบ้าง

- กรองตามวันที่ ระบบต้นทาง กองทุน (NHSO / FDH) สถานะ
- แสดงเลข `vn` เพื่อให้ Admin อ้างอิงกลับไปที่ รพ. ได้
- **ห้ามแสดงข้อมูลส่วนตัวผู้ป่วย** (ดู CLAUDE.md ข้อ 2.1)

---

## ปัญหา (`/issues`)

**ตอบคำถาม:** ปัญหาอะไรเยอะสุด และแก้ยังไง

แสดง 2 ชั้น เพราะรหัสข้อผิดพลาดมี 654 ตัว เรียงเป็นลิสต์เดียวไม่มีใครอ่านจบ

**ชั้นที่ 1: กลุ่มใหญ่**

| แสดง | ตัวอย่าง |
|---|---|
| อันดับ | 1 |
| ชื่อกลุ่ม | รหัสเบิกและค่าใช้จ่าย (C) |
| จำนวน | 111,984 รายการ |
| รพ. ที่เจอ | 662 แห่ง |
| แนวโน้ม | +38% |

**ชั้นที่ 2: กดเข้าไปเห็นรหัสย่อย**

- รหัสจริง เช่น `C001`
- ข้อความของ สปสช.
- วิธีแก้ของ สปสช.
- ธง AllowClaim ว่าแก้แล้วส่งใหม่ได้ไหม
- รายชื่อ รพ. ที่เจอรหัสนี้

**ต้องแยกให้เห็นชัด:** รายการที่ `AllowClaim = N` คือเงินที่หายไปแล้ว
ไม่ใช่งานที่รอแก้ ต้องนับแยกจากกัน

## รายงาน (`/reports`)

**ตอบคำถาม:** ขอสรุปเอาไปเสนอ

- สรุปรายวัน รายเดือน
- แยกตามเขตสุขภาพ ระบบต้นทาง กองทุน
- ส่งออก Excel และ PDF

---

## ตั้งค่าระบบ (`/admin`)

เฉพาะ role `admin`

- จัดการผู้ใช้และสิทธิ์
- จัดการ API key ของแต่ละ รพ.
- ตั้งเกณฑ์แจ้งเตือน (อัตราสำเร็จต่ำกว่าเท่าไรถึงเตือน)
- ดู log การใช้งาน

---

## เข้าสู่ระบบ (`/login`)

- เข้าด้วยบัญชี BMS Life
- ตอนนี้ mock ผู้ใช้ไว้ที่ `components/layout/app-shell.tsx`
- ของจริงต่อ REST API ของ BMS Life แล้วเก็บ token ใน httpOnly cookie

**ยังไม่รู้:** รูปแบบ API ของ BMS Life ต้องถามก่อนทำ
