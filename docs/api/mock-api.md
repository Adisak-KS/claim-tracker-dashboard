# API จำลอง (Mock API)

ระหว่างยังไม่มี backend จริง ระบบใช้ API route ของ Next.js เป็นตัวจำลอง
อยู่ที่ `frontend/src/app/api/`

## ทำไมต้องมี API จำลอง ไม่ import ข้อมูลตรง ๆ

ถ้า component เรียกฟังก์ชันสร้างข้อมูลตรง ๆ จะไม่มี
สถานะกำลังโหลด ไม่มี error ให้จัดการ และไม่มีการแบ่งหน้า
พอต่อของจริงจะพบว่าหน้าจอไม่รองรับอะไรเลย

การมี HTTP จริงคั่นไว้ ทำให้หน้าจอถูกทดสอบกับสถานการณ์จริงตั้งแต่แรก
พอ backend มาแล้วเปลี่ยนแค่ `NEXT_PUBLIC_API_BASE` ไม่ต้องแก้หน้าจอ

## รายการ endpoint

### `GET /api/dashboard`

| พารามิเตอร์ | ชนิด | ค่าเริ่มต้น | ความหมาย |
|---|---|---|---|
| `days` | number | 7 | ย้อนหลังกี่วัน |

ตอบกลับ: ยอดรวม อัตราสำเร็จ กราฟแนวโน้ม อันดับปัญหา รพ. ที่ต้องช่วย

### `GET /api/hospitals`

| พารามิเตอร์ | ชนิด | ความหมาย |
|---|---|---|
| `q` | string | ค้นหาจากชื่อ รหัส หรือจังหวัด |
| `zone` | string | กรองเขตสุขภาพ (1-13 หรือ `all`) |
| `system` | string | กรองระบบต้นทาง (HOSxP, EHP, NHIP, OTHER) |
| `status` | string | `problem` · `silent` · `healthy` |
| `sort` | string | `failedCount` · `successRate` · `totalSent` · `name` |
| `page` | number | หน้าที่เท่าไร เริ่มที่ 1 |
| `pageSize` | number | กี่แถวต่อหน้า สูงสุด 100 |

### `GET /api/issues`

ตอบกลับ: รหัสปัญหาเรียงตามจำนวน พร้อมคำอธิบายและวิธีแก้

## ข้อมูลจำลอง

สร้างจาก `frontend/src/mocks/generator.ts`

| ตัวเลข | ค่า |
|---|---|
| โรงพยาบาล | 5,012 แห่ง |
| รายการต่อวัน | ประมาณ 1.6 ล้าน |
| เขตสุขภาพ | 1 ถึง 13 |

### ใช้ตัวสุ่มที่ seed ได้

ข้อมูลจำลองต้องคงที่ทุกครั้งที่เรียก **ห้ามใช้ `Math.random`**

ถ้าตัวเลขเปลี่ยนทุก refresh จะแยกไม่ออกว่าที่เห็นต่างไปเพราะแก้โค้ดถูก
หรือเพราะข้อมูลสุ่มใหม่ ทำให้ทดสอบอะไรไม่ได้เลย

### หน่วงเวลาไว้ให้เห็น loading

แต่ละ endpoint มี `setTimeout` 300-450ms เพื่อให้เห็น skeleton จริงตอนพัฒนา
**ของจริงต้องลบบรรทัดนี้ออก**

## ข้อควรรู้เมื่อต่อของจริง

- ตัวเลขในระบบจำลองคำนวณจากชุดข้อมูลเดียวกันทั้งหมด
  KPI กราฟ และตารางจึงตรงกันเสมอ ของจริงต้องรักษาคุณสมบัตินี้ไว้
- ยอดรวมในการ์ด KPI เป็นยอด**สะสมทั้งช่วง** ไม่ใช่ของวันเดียว
  ป้ายกำกับต้องบอกช่วงให้ชัด ไม่งั้นผู้ใช้เข้าใจผิด
